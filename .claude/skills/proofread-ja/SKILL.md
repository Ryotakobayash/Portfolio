# proofread-ja

AI が書いた日本語にありがちな言い回し（「土台」「〜した瞬間」「効く」など）を textlint で検出し、言い換える。

## いつ使うか

- Claude が `src/content/posts/` や `src/content/talks/` の本文を書いた・書き換えたとき。PostToolUse フック（`scripts/hooks/textlint-content.mjs`）が編集のたびに textlint を実行し、指摘を返してくる
- ユーザーに校正を頼まれたとき

## 手順

1. 対象ファイルに textlint をかける。フックの指摘が届いているなら、それを使ってよい

   ```bash
   pnpm exec textlint <ファイル>
   ```

2. 指摘を「Claude が今回書いた・書き換えた箇所」と「ユーザーが書いた既存の文章」に分ける
3. Claude が書いた箇所は言い換える。文脈に合う表現を選び、指摘に出ている候補をそのまま機械的に当てはめない
4. ユーザーが書いた既存の文章は直さない。件数と行番号だけを伝え、直すかどうかはユーザーに任せる。頼まれた場合だけ言い換え案を出す
5. 直したあと、もう一度 textlint をかけて指摘が消えたことを確かめる

## 言い換えるときの注意

- `--fix` で自動置換しない。辞書の `expected` は候補の一例で、文脈によっては合わない
- 意味が変わるなら言い換えない。技術用語・固有名詞・引用・コードの中の語は、指摘されても残してよい。残した場合は理由を一言添える
- 語を差し替えるだけで済ませず、必要なら文ごと組み直す。「AI っぽさ」は語彙より、抽象的なまとめ方や大げさな修飾から出ていることが多い
- 名詞以外を太字にして強調しない（このリポジトリの文体ルール）

## 辞書に語を足す

`textlint-rule-preset-ai-words-ja` は検出語を追加できないので、追加したい表現は `.textlint/prh.yml` に書く。

```yaml
rules:
  - expected: 言い換え候補
    pattern: 検出したい表現
    prh: なぜ不自然か、どう言い換えるか
```

## 関連

- 設定: `.textlintrc.json`（MDX は `textlint-plugin-mdx` で検査）
- 全体を検査: `pnpm lint:text`（既存の記事にも指摘が残っているので、エラーになっても公開は止めない）
